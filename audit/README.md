# audit/ — review channel

This folder exists so a reviewer working from the published repository (a Claude
Chat auditor, or a person) can check this wiki without access to the session that
built it. Git is the transport: I write here, you commit replies to
`audit/replies/`.

## What this wiki is

`GA.html` is a single-file TiddlyWiki (4.3 MB, opens offline, no server) built
from the Markdown under `wiki/`. The Markdown is the source of truth; the HTML is
a build artifact. `wiki/` also renders directly in llmwiki — standard Markdown
links, `$…$` math, footnote citations.

Three bodies of work, from three sources — see `wiki/overview.md`, which also
states what the wiki does *not* claim.

## What to check

In descending order of how much a wrong answer would matter:

1. **Are the claims the sources' claims?** `wiki/concepts/` is my synthesis and is
   the most likely place for a plausible-sounding error. Each page names its
   source; the gold pages under `wiki/gold/` carry the original scan.
2. **Is the mathematics right?** Every formula was hand-typeset from a source,
   then checked against the machine extraction. `wiki/gold/*.md` pairs my LaTeX
   with the scan it should match. One error was already found this way and fixed
   (see `OPEN-QUESTIONS.md`, item 1).
3. **Is imported material honestly labelled?** `wiki/chapters/` was produced
   mechanically from a drilled PDF, not read. It should not read as though I had
   read it.
4. **Is anything asserted without a citation?** Every factual claim should trace
   to a source page or a gold unit.

## What is already verified, so you need not re-derive it

`verification.json` is generated by `build/verify.py` — re-run it to confirm:

| check | result |
|---|---|
| Markdown pages | 115 |
| math expressions compiling under KaTeX | 452 / 452 |
| broken links or images | 0 |
| unreferenced pages | 1 (`log.md`, by design) |
| scan crops | 53 |

These are structural checks. **They say nothing about whether the content is
correct** — that is what this review is for.

## Reports from this side

`audit/reports/` holds one file per change I report — what changed, the evidence
it works, and what it does not fix. `replies/` is yours; `reports/` is mine.

## How to reply

Add one file per review to `audit/replies/`, named `YYYY-MM-DD-<topic>.md`, using
`replies/TEMPLATE.md`. Commit it. Anything under `replies/` is yours; I will not
rewrite it.

Please separate:

- **Defect** — a claim that is wrong, with the evidence that it is wrong.
- **Unsupported** — a claim that may be true but is not backed by a cited source.
- **Judgement** — a choice you would have made differently. These are useful, but
  they are not defects, and I will treat them as choices unless you show harm.

If you cannot verify something without the source PDF, say so rather than
guessing — the verbatim extractions are not published (see below).

## What is not in the repository

- `raw/` — verbatim full-text extractions of the source documents. These are
  third-party copyrighted works (an AMS chapter, a Springer volume); publishing
  the full text is not mine to do, so it is gitignored and the built wiki no
  longer bundles it. Equation *scans* are published as small excerpts because
  they are what makes a formula checkable.
- `.llmwiki/`, `build/tw/` — derived, rebuildable.

## Rebuilding

```bash
./build/build.sh          # wiki/ -> GA.html
python3 build/verify.py   # regenerate verification.json
```

Needs `node` and a TiddlyWiki install; KaTeX is vendored under `build/vendor/`,
so the build runs offline.
